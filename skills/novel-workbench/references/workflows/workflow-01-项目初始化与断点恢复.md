# 工作流01：项目初始化与断点恢复

## 新项目

1. 先确认题材、主角、核心冲突和标题；不能因为工作区为空而猜测标题。
2. 将确认标题转换为安全目录名：去掉书名号，斜杠、冒号等路径保留字符替换为短横线，连续空格压缩为一个短横线。
3. 建立 `novel-projects/YYYYMMDD-HHmmss-安全标题/`，例如 `novel-projects/20260715-142530-不要相信我/`；可以使用 `scripts/init_novel_project.py`，它只会在目标项目库内创建目录。
4. 按标准目录创建项目文件夹，并生成 `项目索引.md`、项目元数据、`01-项目管理/创作配置-偏好与内容边界.json` 和写作计划。
5. 将本次确认的偏好写入项目内配置；不得在 `novel-projects/` 或工作区根目录另建偏好文件。
6. 若标题或规格尚未确认，转入工作流02；不要直接开始写正文。

## 续写项目

按以下顺序查找项目：

1. 用户明确指定的项目路径。
2. 项目索引中标记为 `in_progress` 的项目。
3. 写作计划中存在 `in_progress`、`failed` 或未完成活动范围的项目。

恢复前读取：

- 项目索引和项目元数据
- `01-项目管理/创作配置-偏好与内容边界.json`
- 写作计划与活动范围
- 最近完成章节及连续性台账
- 大纲锁定文件
- 最近一次审核报告

恢复时优先处理 `in_progress`，其次处理 `failed`，最后认领活动范围内编号最小的 `pending` 章节。不得因为文件存在就假定章节已经通过审核。

## 异常情况

- 计划 JSON 损坏：先复制原文件，再根据正文文件和审核记录重建状态。
- 项目没有 `创作配置-偏好与内容边界.json`：只在该项目的 `01-项目管理/` 内补建，不回退到工作区根目录。
- 找不到章节路径：停止写作，运行路径检查脚本。
- 范围不明确：只询问范围，不重新询问已经确认的题材和人物。
