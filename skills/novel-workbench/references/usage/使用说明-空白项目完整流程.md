# 小说创作工作台：空白项目完整使用说明

## 这份说明解决什么问题

本文说明在一个没有小说档案的空白工作区中，如何触发 `novel-workbench`，它会询问什么、创建什么、什么时候开始写作，以及如何续写、指定章节和出版级整理。

## 一、最小触发方式

新建小说可以直接这样说：

```text
使用 $novel-workbench 帮我创作一部中文小说。
```

如果已经有创意，最好一次提供：

```text
使用 $novel-workbench 帮我创作一部生态恐怖与废土惊悚结合的中篇小说。
第一主角是女性，暂定群像叙事；我想写身份、记忆和现实都不可信的故事。
```

指定篇幅、章节范围或内容尺度也可以在第一次请求中说明。

## 二、空白工作区中的触发条件

Skill 被加载不会自动创建小说目录。必须同时满足：

1. 用户明确要求使用本 Skill 创作、规划或续写小说。
2. 当前工作区找不到用户指定的现有项目。
3. 用户尚未确认的题材、主角、冲突和标题不会被模型擅自补成最终设定。

如果只是打开一个空文件、输入“你好”或只说“帮我写点东西”，不会直接创建完整项目；最多进入需求澄清。

## 三、从空白到项目的完整触发链

### 0. 初始化检查

读取当前工作区是否存在项目。新项目不读取工作区根目录的全局偏好文件；偏好只在项目创建后保存到该项目的 `01-项目管理/创作配置-偏好与内容边界.json`。

### 1. 第一层需求访谈

依次确认三件事：

- 题材、核心创意和阅读感受
- 第一主角、群像规模、人物欲望和弱点
- 核心冲突、失败代价和终局方向

用户已经明确的内容不重复询问。

### 2. 第二层规格确认

根据题材补充确认：

- 世界观和时代背景
- 叙事视角、人称和时间结构
- 基调、黑暗度和允许的内容尺度
- 主题、读者定位和风格参考
- 总章数、分卷数和单章字数范围
- 是否需要群像声音表、概念词典和作者真相封存
- 本轮写作范围与审核方式

用户说“按你的建议”时，模型可以代拟方案，但要把代拟内容标成建议，不能当成用户原始要求。

### 3. 标题确认

生成 3—8 个候选标题并说明定位。用户确认标题后，才开始创建项目目录。

### 4. 创建项目目录

目录格式固定为：

```text
novel-projects/YYYYMMDD-HHmmss-安全标题/
```

例如：

```text
novel-projects/20260715-142530-不要相信我/
```

安全标题处理规则：去掉《》；将斜杠、冒号等路径字符替换为短横线；连续空格压缩为一个短横线。

项目初始化脚本为 `scripts/init_novel_project.py`。它只在用户指定的项目库中创建标准目录，不读取工作区根目录偏好，也不会覆盖非空目录。

### 5. 生成项目配置

至少生成：

```text
项目索引.md
01-项目管理/
├── 项目元数据-标题与规格.json
├── 创作配置-偏好与内容边界.json
└── 章节写作计划-状态与范围.json
```

`创作配置-偏好与内容边界.json` 属于本书项目配置，不放在工作区根目录、`novel-projects/` 根目录或 Skill 目录。

### 6. 生成故事档案

根据题材生成：

- 角色档案
- 世界观设定
- 概念词典
- 群像声音表
- 伏笔与揭晓矩阵
- 连续性台账
- 作者真相封存档案
- 全书和分卷大纲

作者真相档案只供写作与审核使用，不得复制进正文。

### 7. 规划确认

展示一页以内的规划摘要，包括：题材、主角、核心冲突、视角、篇幅、分卷、内容尺度、主要角色和活动范围。

在用户确认前，只做规划，不批量创作正文。

### 8. 写作模式与活动范围

默认使用逐章串行模式。用户可以指定：

- 完整小说
- 某一卷
- 第 N—M 章
- 先写若干章并自动审核

范围写入 `activeScope`。`stopAfterScope` 为 `true` 时，末章审核后停止，不自动进入下一卷。

### 9. 逐章创作

每章按以下闭环执行：

```text
读取本章规划
→ 读取人物、连续性和真相边界
→ 写纯正文
→ 字数与机械质量检查
→ 人物、因果、视角和概念冷读
→ 回写计划、台账和伏笔
→ 进入范围内下一章
```

正文文件只包含章节标题和正文，不包含章节概要、作者备注、审核结果或 HTML 注释。

### 10. 分卷审核

范围内章节完成后，执行路径、字数、正文纯净度、人物一致性、概念可读性、伏笔公平性和节奏审核，结果写入 `05-写作过程/`。

### 11. 出版级整理

全书完成后，执行正文清理、语言精修、敏感内容审读、目录校验和终稿检查。出版报告放在 `06-出版与审校/`，不放入 `正文/`。

## 四、创建完成后的目录形态

```text
novel-projects/时间戳-标题/
├── 项目索引.md
├── 01-项目管理/
├── 02-故事圣经/
├── 03-大纲与分卷/
├── 04-连续性与伏笔/
├── 05-写作过程/
├── 正文/
│   ├── 正文目录.md
│   ├── 第一卷-卷名/
│   │   ├── 第01章-标题.md
│   │   └── 第02章-标题.md
│   └── 第二卷-卷名/
├── 06-出版与审校/
└── 99-归档/
```

## 五、已有项目如何使用

继续写作：

```text
使用 $novel-workbench 继续 novel-projects/20260715-142530-不要相信我，完成第31—40章并自动审核。
```

审核项目：

```text
使用 $novel-workbench 检查这个项目的连续性、伏笔、人物声音和正文纯净度，不要改正文。
```

出版整理：

```text
使用 $novel-workbench 对这个项目执行出版级精修，只处理正文和出版审校目录。
```

恢复中断：

```text
使用 $novel-workbench 从这个项目的上次断点继续，不重新询问已经确认的设定。
```

## 六、用户何时需要再次介入

需要用户确认的节点：

- 题材、主角和核心冲突尚未明确时
- 标题尚未确认时
- 故事圣经和分卷大纲生成后
- 活动范围或终局方向发生改变时

用户明确授权“完成第 N—M 章并自动审核”后，正常写作和审核过程中不再次询问。只有范围冲突、文件损坏、设定互相矛盾或无法安全修复时才暂停并报告。

## 七、模型使用说明

Skill 不会自动切换模型。创作模型、审核模型可以记录在项目元数据中，但实际模型切换由用户或运行环境完成。

## 八、维护者回归测试

运行 `python scripts/smoke_test.py` 会在临时目录创建一个测试项目，写入一章测试正文，并依次执行路径、计划、纯正文、字数和质量检查。测试结束后临时目录会自动清理，不会在当前工作区生成小说项目。
